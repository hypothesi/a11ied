# VQ-04 manual run

- Task id: `VQ-04`
- Evidence type: `manual-cli`
- Source plan: `internal-docs/plans/a11ied-vitest-command-queue-plan.md#VQ-04`
- Gherkin: `internal-docs/specs/gherkin/17-test-command-queue.feature`,
  scenarios `The Vitest fixture reports an unawaited failure on the test`,
  `The Vitest fixture passes a test that awaits a rejection`, and
  `The Vitest fixture reports a test body error once`
- Scope: what a test author sees when a queued command fails under the
  `a11ied/vitest` fixture

## Steps

1. Ran the on-purpose failing fixture file with Vitest's default reporter, the
   way a test author runs it:

   ```sh
   npx vitest run --config vitest.queued-failure.config.ts
   ```

2. Read the report for each of the three tests in
   `packages/cli/test/fixtures/queued-failure.test.ts`.

## Observations

- The unawaited failure is reported under the test's own name, not under a
  hook, with the `ScreenReaderAssertionError` message and a code frame at the
  `sr.expectSpoken('Refund')` line.
- The test that awaits the rejection with `expect(...).rejects.toThrow` passes,
  and the `sr.next('button')` queued after it ran.
- The test that throws from its body reports that one error only. The queued
  check that also failed was not reported a second time.

Pass.
