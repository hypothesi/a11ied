# v0.1.0 release readiness

This file is the explicit release record for the first public milestone.

## release path

### packages

1. Run `npm run standards` from the repo root.
2. Run `npm test` from the repo root.
3. Run `npm run pack:check` to confirm every public workspace packs cleanly.
4. Publish the public workspaces through the `publish-packages` GitHub Actions workflow (or a published GitHub release event).
5. Smoke the released CLI (`a1 doctor`) and the released library and MCP entry points before announcing the release.

### docs

1. Run `npm run build --workspace @a11ied/docs`.
2. Publish the generated static output from `packages/docs/dist/`.
3. Confirm the live site serves the quickstart, install, targets, coverage, applicability, screen reader and testing guides, CLI reference, MCP reference, and API reference routes. `packages/docs/src/lib/nav.ts` lists every route the site should carry.

### agent skill

1. Review `packages/skills/a11ied/SKILL.md` against the released CLI and MCP behavior.
2. Review `packages/skills/a11ied/agents/openai.yaml` so the description matches the release.
3. Publish the skill bundle from `packages/skills/a11ied/` together with the docs update so agents and humans read the same rules.
4. Review `packages/skills/a11ied-audit/SKILL.md and its resources` against released CLI and MCP behavior.
5. Review `packages/skills/a11ied-audit/agents/openai.yaml` and publish the bundle with its docs pages.

## release requirements

- all CI checks pass
- one manual macOS VoiceOver smoke run passes
- one manual Windows NVDA smoke run passes
- deferred items below are reviewed and accepted explicitly

### docs rewrite, 2026-11-24

Every page of `packages/docs` was rewritten and the shell restyled. Checked against the production build, served under `/a11ied/`.

- All 22 routes in `packages/docs/src/lib/nav.ts` and the new 404 page build: 166 pages in total. Every internal link and fragment on the docs pages resolves. The 8 that do not are placeholder links inside test fixtures: the practice page's `#general` and `#billing`, and the isolated support cases.
- `a1 axe --level AA` reports no violation on 26 pages: the 21 prose pages, the 404 page, `/support/`, and one feature, test, and ARIA-AT plan page. Both contrast findings from 2026-11-23 are fixed: the `.eyebrow` label is gone, and the simulated column on `/support/` is no longer partly transparent. Bead `a11ied-proof-plm` is closed.
- The same 26 pages do not scroll sideways at 390, 768, or 1440 pixels wide.
- axe leaves one check undecided on every page: `aria-controls` on the search button, which axe never decides when `aria-haspopup` is set. The dialog it names is in the page. On the support feature and test pages axe also cannot measure the small WebView, MUST, and SHOULD tags, because a row covers them; by calculation they are 8.15:1 and 8.49:1.
- Site search was added with Pagefind 1.6.0 (MIT), indexed by `npm run build`. Support pages are weighted below prose pages. Opened by keyboard with the simulated reader, a query announced its result count and the first result loaded under `/a11ied/`. The shortcut hint on the search button is hidden, because with it the button failed 2.5.3 Label in Name.
- Each section heading links to itself, and the anchors moved from the sections to the headings. `guides/screen-reader#browser-support`, which `a1 doctor` prints, still resolves.
- Output blocks are real `a1` output captured against the practice page and kept in `packages/docs/src/samples/`. The test and API samples were type-checked and run before they were written into the pages.
- Corrected against the CLI: the check report header and hand-check wording, the relevance state name (`relevant`, not `applicable`), the claim that a criterion can be `automated` (none is in WCAG 2.2), a thin-page warning the CLI no longer prints, `pattern record` options that no longer exist, and `showWcagCoverageSummary`, which is `showWcagTestMethodSummary`.
- Two independent reviews ran against the built site: a new-user walkthrough that ran every quickstart and practice command, and an accuracy audit of every documented command, option, tool, and export. Their findings were verified and fixed. The larger ones: "ten problems" meant both ten failing elements and ten defects; `a1 doctor` in the quickstart could send a new Mac user into VoiceOver setup, so it is now `a1 doctor --task scan`; exit code 1 was undocumented; `runAxe` was said to return a verdict; command blocks cut off long addresses on a phone.
- After review by the maintainer, `/` became a separate marketing home page and the overview moved to `/overview`. The halftone circle and the red shadow behind code blocks came back. The circle is drawn so that no text sits over the dots, which keeps heading contrast measurable. With these changes 27 pages were rechecked: no violations at Level AA and no sideways scroll at 390, 768, or 1440 pixels.
- A third independent review covered the home page. Its findings were verified and fixed: the hero now runs as copied and shows a dialog that opens without being announced, the count of ten flagged elements is told apart from the ten problems, two overstated claims were corrected, and the agent section shows a real tool result. Copy buttons are now named after what they copy.
- The repository has no license file, so the site no longer calls the project open source.
- Product behaviors found on the way are filed as beads `a11ied-proof-nt9`, `a11ied-proof-ft6`, `a11ied-proof-n5g`, and `a11ied-proof-ods`.
