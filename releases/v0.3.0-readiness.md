# v0.3.0 release readiness

This file is the explicit release record for the first public milestone.

## release path

### packages

1. Run `npm run standards` from the repo root.
2. Build every publishable workspace package.
3. Publish in dependency order so downstream packages never point at versions that do not exist yet:
   - `@a11ied/contracts`
   - `@a11ied/guidepup`
   - `@a11ied/wcag-data`
   - `@a11ied/wcag-engine`
   - `@a11ied/core`
   - `@a11ied/storybook`
   - `@a11ied/mcp-server`
   - `a11ied`
4. Smoke the published CLI and MCP entrypoint before announcing the release.

### docs

1. Run `npm run build --workspace @a11ied/docs`.
2. Publish the generated static output from `apps/docs/dist/`.
3. Confirm the live site serves the release checklist and verification-semantics routes.

### agent skill

1. Review `skills/a11ied/SKILL.md` against the shipped CLI and MCP behavior.
2. Review `skills/a11ied/agents/openai.yaml` so the description matches the release.
3. Publish the skill bundle from `skills/a11ied/` together with the docs update so agents and humans read the same rules.

Milestone integration review ran on 2026-04-08.

Cross-surface smoke coverage completed for:

- built CLI WCAG lookup

- built CLI Storybook target resolution

The integration pass confirmed those surfaces work together against the local fixture targets and Storybook fixture server.

Docs UX remediation review ran on 2026-04-09 against the built static site.

That review covered:

- homepage on desktop and mobile
- workflows route on desktop and mobile

- MCP usage

The review confirmed the docs now expose a task-first entry path, a mobile navigation drawer that does not bury content below the fold, and a cleaner separation between workflow guidance and subsystem reference.

## deferred items

- Real-target VoiceOver and NVDA smoke runs are still manual release gates, not PR CI jobs.
- Package publication is still a manual sequence. There is no automated publish workflow yet.
- `npm run standards` stays green, but the verification-heavy Vitest path is slow. `packages/cli/src/testing/handlers-verify-level.test.ts` took about 169 seconds in the milestone review, so more verification coverage will need performance work instead of blind test growth.
