## Scope

This manual run covers the first applicability pass in `wcag-engine`:

- applicability inputs stay pure and runtime-agnostic
- quickref tags provide first-pass hints instead of hard-coding every criterion
- representative fixtures classify obvious cases for auth, status messages, dialogs, and custom widgets
- unresolved widget cases stay `unknown` instead of being flattened into `not-detected`

## Steps

1. Add fixture-backed applicability inputs for `basic-page.html`, `status-message.html`, `auth-login.html`, `dialog.html`, and `custom-widget.html`.
2. Add engine exports for supported applicability states and signal categories.
3. Implement `getCriterionApplicability` and `listApplicableCriteria` as pure functions over structural signals plus criterion tags.
4. Keep the heuristics conservative:
   - treat explicit auth and live-region signals as strong evidence
   - treat dialog and overlay structure as relevant interaction signals
   - leave custom-widget-only cases unresolved when there is not enough structure to justify stronger claims
5. Add automated tests in `packages/contracts/src/index.test.ts` and `packages/wcag-engine/src/index.test.ts` for the mapped scenarios.
6. Run:
   ```sh
   npx vitest run packages/contracts/src/index.test.ts
   npx vitest run packages/wcag-engine/src/index.test.ts
   npm run typecheck --workspace @a11ied/wcag-engine
   npm run standards
   ```
