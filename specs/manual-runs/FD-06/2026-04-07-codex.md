## Scope

This manual run covers the first real `wcag-engine` implementation:

- criterion lookup resolves both canonical ids and slugs
- level listing works by requested WCAG version
- local search returns ranked results with match metadata
- coverage and verification strategy lookups join the generated artifacts back to the canonical criterion
- unsupported ids and versions fail with typed engine errors

## Steps

1. Create `packages/wcag-engine` and wire it to `packages/wcag-data/data/generated`.
2. Implement synchronous read APIs for `getCriterion`, `listCriteriaByLevel`, `searchCriteria`, `getCoverage`, `getQuickrefTags`, and `getVerificationStrategy`.
3. Add typed `WcagEngineNotFoundError` and `WcagEngineValidationError` wrappers around the shared contract payloads.
4. Add automated tests in `packages/wcag-engine/src/index.test.ts` for the mapped engine-query scenarios.
5. Run:
   ```sh
   npm run typecheck --workspace @a11ied/wcag-engine
   npm run standards
   ```
