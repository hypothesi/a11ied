## Scope

This manual run covers the first real low-level `drive` action layer:

- runtime validation for `--session` versus `--ephemeral`
- persistent action commands on an existing session
- one-shot ephemeral actions that leave no session metadata behind
- `read`, `logs`, `clear-logs`, and `checkpoint` behavior over the broker-backed virtual target

## user-surface exercise

I manually exercised the built CLI action surface from `dist` after resetting the generated state directory:

```sh
rm -rf .a11ied
node packages/cli/dist/cli.js drive next --target virtual --json
node packages/cli/dist/cli.js drive next --target virtual --ephemeral --json
if [ -d .a11ied/state/sessions ]; then find .a11ied/state/sessions -type f | wc -l; else echo 0; fi
node packages/cli/dist/cli.js drive start --target virtual --json
node packages/cli/dist/cli.js drive read --session drv_e7e35711-927a-409f-b880-c266da33e91e --json
node packages/cli/dist/cli.js drive next --session drv_e7e35711-927a-409f-b880-c266da33e91e --json
node packages/cli/dist/cli.js drive clear-logs --session drv_e7e35711-927a-409f-b880-c266da33e91e --json
node packages/cli/dist/cli.js drive checkpoint --session drv_e7e35711-927a-409f-b880-c266da33e91e --label after-clear --json
node packages/cli/dist/cli.js drive logs --session drv_e7e35711-927a-409f-b880-c266da33e91e --json
node packages/cli/dist/cli.js drive stop --session drv_e7e35711-927a-409f-b880-c266da33e91e --json
if [ -f .a11ied/state/sessions/drv_e7e35711-927a-409f-b880-c266da33e91e.json ]; then echo still-there; else echo removed; fi
```

Observed result:

- `drive next --target virtual --json` exited with code `2` and returned the expected `missing-session` usage error
- `drive next --target virtual --ephemeral --json` exited with code `0`, returned action output for one navigation step, and left the session metadata directory empty afterward
- `drive read --session ... --json` exited with code `0` and returned `lastSpokenPhrase`, `itemTextLog`, and `logCursor`
- `drive clear-logs --session ... --json` exited with code `0` and returned empty `spokenPhraseLog` and `itemTextLog`
- `drive checkpoint --session ... --label after-clear --json` exited with code `0` and appended the named checkpoint to the session state
- `drive logs --session ... --json` exited with code `0` and still showed empty logs after the clear
- `drive stop --session ... --json` exited with code `0`, and the persisted session metadata file was gone afterward
