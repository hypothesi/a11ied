## user-surface exercise

I manually exercised the built CLI surface from `dist` against the local fixture server on `http://127.0.0.1:4173`:

```sh
node packages/cli/dist/cli.js run axe --url http://127.0.0.1:4173/button-name-failure.html --criterion 4.1.2 --json
node packages/cli/dist/cli.js run axe --url http://127.0.0.1:4173/button-name-failure.html --criterion 4.1.2
node packages/cli/dist/cli.js run axe --url http://127.0.0.1:4173/contrast-failure.html --level AA --json
node packages/cli/dist/cli.js run axe --url http://127.0.0.1:4173/basic-page.html --rule color-contrast --json
node packages/cli/dist/cli.js run axe --story-id forms-login--default --criterion 4.1.2 --json
node packages/cli/dist/cli.js run axe --url http://127.0.0.1:4173/basic-page.html --rule frame-tested --json
```

Observed result:

- `--criterion 4.1.2 --json` exited with code `0` and returned one violation, `button-name`, plus normalized pass rows for `aria-hidden-body` and `nested-interactive`
- the human-readable `--criterion 4.1.2` run printed:
  - `Selection: criterion=4.1.2`
  - `Violations: button-name (critical)`
  - `Passes: aria-hidden-body, nested-interactive`
  - `Incomplete: none`
- `--level AA --json` exited with code `0` and returned `color-contrast` and `color-contrast-enhanced` in violations on the contrast fixture
- `--rule color-contrast --json` exited with code `0` and returned only the requested rule id in the normalized result
- `--story-id forms-login--default --criterion 4.1.2 --json` exited with code `2` and returned the `storybook-targets-unavailable` error
- `--rule frame-tested --json` exited with code `0` and preserved `frame-tested` in the `incomplete` collection for the updated basic-page fixture
