## user-surface exercise

I manually exercised the built CLI surface itself against a live local fixture server:

```sh
python3 -m http.server 4173 --bind 127.0.0.1 -d packages/cli/test/fixtures
node packages/cli/dist/cli.js wcag levels --json
node packages/cli/dist/cli.js wcag show status-messages
node packages/cli/dist/cli.js wcag coverage 4.1.3 --json
node packages/cli/dist/cli.js inspect applicable --url http://127.0.0.1:4173/status-message.html --json
node packages/cli/dist/cli.js inspect criterion 4.1.3 --url http://127.0.0.1:4173/status-message.html
node packages/cli/dist/cli.js inspect applicable --story-id forms-login--default --json
```

Observed result:

- the first manual pass failed with `ERR_MODULE_NOT_FOUND` because the built CLI could not resolve `@a11lied/wcag-engine` from the packaged runtime
- `npm install` fixed the workspace-runtime dependency resolution so the built CLI could actually run as shipped
- `wcag levels --json` exited with code `0` and returned the default WCAG `2.2` levels `A`, `AA`, and `AAA`
- `wcag show status-messages` exited with code `0` and rendered the criterion heading, summary, normative text, and understanding URL in text mode
- `wcag coverage 4.1.3 --json` exited with code `0` and returned the criterion, coverage state `hybrid`, and strategy `status_message_probe`
- `inspect applicable --url .../status-message.html --json` exited with code `0` and returned URL target metadata, detected signals, and an applicability matrix
- `inspect criterion 4.1.3 --url .../status-message.html` exited with code `0` and rendered the criterion state, matched signals, and reasoning in text mode
- `inspect applicable --story-id forms-login--default --json` exited with code `2` and returned the expected `storybook-targets-unavailable` usage error
